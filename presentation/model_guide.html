1. Problem & framing

Task. Binary classification: predict the historical credit_decision (1 = approved, 0 = rejected) for 5,000 personal-loan applications in May 2026, given 25,000 historical decisions from 2022–April 2026.

Metric. Accuracy on hard 0/1 labels. The probability→label threshold is therefore part of the model.

What we are really predicting: the analyst's historical decision, not whether the loan ultimately defaulted. Any analyst bias is baked into the target. Important for the ethics section.

Time dimension. Train ends April 2026, test is entirely May 2026 → out-of-time evaluation. Validation must respect time, not just be random.

2. The data

SetRowsPeriodTarget
Train25,0002022-01 → 2026-04✅ included

Target balance: 51.98% approved / 48.02% rejected. A majority-class guess only scores 0.52, so every accuracy point must be earned.

Public leaderboard = 40% of test (2,000 rows). Private leaderboard = 60% (3,000 rows) — only the private is graded.

3. The three traps

The professor wrote in the brief: "Do not assume that every column is equally reliable." Treating that line literally, we hunted for sabotaged columns. We found three.

Trap 1 — internal_code: planted leak

Correlates with the target +0.92 in train. A trivial rule internal_code > 50 hits 99.1% accuracy in train. Looks like the best feature in the dataset.

Detection — the opinion-probe. analyst_opinion is the same 60 fixed templates in train and test. Their per-template approval rate is a stable proxy for the underlying signal. Any genuine feature should correlate with that proxy the same way in train and in test. internal_code doesn't:

opmap = train.groupby('analyst_opinion').credit_decision.mean()  # 60 templates
tr_op = train.analyst_opinion.map(opmap)
te_op = test.analyst_opinion.map(opmap)

train.internal_code.corr(tr_op)   # +0.46  → real signal
test.internal_code.corr(te_op)    # ≈ 0.00 → scrambled in test

Same marginal distribution in train and test, but in test the values are decoupled from every other risk feature. The values were scrambled.

DROP Without this catch, the model would score ~99% in cross-validation and ~52% on the private 60%.

Trap 2 — external_pd_score: vanishes in test

5.2% missing in train (usable). 100% missing in test (useless at inference time).

Caught in one line: train.isna().mean() vs test.isna().mean().

DROP

Trap 3 — race, religion: the ethical trap

Included as synthetic codes. Measured cost of using them: +0.7pt accuracy (0.859 → 0.866).

Refused on principle. Reasons in §8.

DROP

4. Cleaning & feature engineering

All cleaning lives in one shared module — src/prep.py (v1) and src/prep_v2.py (audit-fixed) — so train and test are cleaned identically. No leakage, fully reproducible.

Most important code snippet — the date fix

def parse_dates(s):
    iso = pd.to_datetime(s, format='%Y-%m-%d', errors='coerce')   # 2022-06-08
    mon = pd.to_datetime(s, format='%b-%Y',    errors='coerce') + pd.Timedelta(days=14)  # Apr-2026
    return iso.fillna(mon)

~50/50 split between the two formats; combine them, dating Mon-YYYY mid-month.

Income unit fix (bimodal histogram)

# log10(ann_income) is bimodal with an empty gap 700..2000:
# half the rows are in thousands, half in units. Rescale below the gap.
inc = pd.to_numeric(df['ann_income'], errors='coerce')
out['ann_income'] = np.where(inc < 700, inc * 1000, inc)

Risk shape features (the inverted-U)

# Linear corr with target was only -0.08 → risk indicators looked useless.
# But approval peaks mid-range (~50) and drops at both extremes:
X['risk12_dev'] = (X.risk12 - 55).abs()
X['risk3_dev']  = (X.risk3  - 55).abs()
X['risk_max']   = X[['risk12','risk3']].max(axis=1)
X['risk_mean']  = X[['risk12','risk3']].mean(axis=1)

These shape features end up at the top of the importance ranking — the raw indicators alone would have been nearly worthless.

Credit-bureau z-scoring (the data-leak fix)

# Three bureaus (FICO, Vantage, SCHUFA) → three different scales.
# v2 fix: compute the z-score stats on TRAIN ONLY, then apply to test.
for c in ['cr_scores_fico','cr_scores_vantage','cr_scores_schufa']:
    mu, sd = train[c].mean(), train[c].std()        # train only, no test peeking
    train[c+'_z'] = (train[c] - mu) / sd
    test[c+'_z']  = (test[c]  - mu) / sd
credit_z = fico_z.fillna(vantage_z).fillna(schufa_z)

6. Model architecture

Three boosting families, mean-blended. Diversity decorrelates errors.

  • 9 × LightGBM — top-3 hyperparameter configs (random-search) × 3 seeds, each 5-fold
  • 3 × XGBoost — 3 seeds, each 5-fold
  • 4 × CatBoost — 2 configs × 2 seeds, each 5-fold (native cat encoding for the 60 opinion templates)

Semi-supervised step (v8/v10): pseudo-label test rows where the base ensemble is ≥97% confident, add them to every training fold at sample_weight = 0.5, refit.

7. Validation strategy

Three independent lenses, each catching a failure mode the others miss.

SchemeWhat it catches
5-fold Stratified K-Fold OOFAverage performance across 25k rows, used to tune the threshold
Time split (train ≤2024 → validate 2025–26)Temporal drift a random split would hide
Rolling next-month harnessThe closest simulation of the real task: train ends 04/2026, test is 05/2026

For each of the last 6 months in train, fit on everything before and predict that month → 2,886 pooled out-of-time predictions. Every experiment was judged here, not on the public leaderboard.

Code: 5-fold OOF + smooth threshold

oof = np.zeros(len(X))
for tr_i, va_i in StratifiedKFold(5, shuffle=True, random_state=42).split(X, y):
    m = lgb.LGBMClassifier(**params)
    m.fit(X.iloc[tr_i], y.iloc[tr_i],
          eval_set=[(X.iloc[va_i], y.iloc[va_i])],
          callbacks=[lgb.early_stopping(150)])
    oof[va_i] = m.predict_proba(X.iloc[va_i])[:, 1]

# Smooth threshold — avoid argmax overfitting OOF noise
ths = np.linspace(0.35, 0.65, 601)
accs = [((oof > t) == y).mean() for t in ths]
smooth_t = ths[np.argsort(accs)[-6:]].mean()   # top-1% average ≈ 0.527

8. Ethics

race and religion are present in the dataset as synthetic codes. Using them gives +0.7pt accuracy (measured).

We refused, for four reasons:

  • Legal: GDPR (EU), ECOA (US), Equal Credit Opportunity Act — protected-attribute use is unlawful in credit decisions.
  • Ethical: the target encodes any historical analyst bias; reproducing it amplifies it.
  • Practical: a model that needs protected attributes can't be deployed.
  • Methodological: the brief flagged these columns — using them would fail the implicit ethics question.

1. Problema e framing

Task. Classificazione binaria: prevedere credit_decision (1 = approvato, 0 = rifiutato) per 5.000 domande di prestito personale di maggio 2026, dati 25.000 esiti storici dal 2022 ad aprile 2026.

Metrica. Accuracy sulla label dura 0/1. Quindi la soglia probabilità→label fa parte del modello.

Cosa stiamo prevedendo davvero: la decisione storica dell'analista, non se il prestito sia poi andato in default. Eventuali bias dell'analista finiscono nel target — importante per la sezione etica.

Dimensione temporale. Il train finisce ad aprile 2026, il test è interamente maggio 2026 → out-of-time. La validazione deve rispettare il tempo, non essere solo random.

3. Le tre trappole

Il prof ha scritto nel brief: "Non assumete che ogni colonna sia ugualmente affidabile." Preso alla lettera, abbiamo cercato colonne sabotate. Ne abbiamo trovate tre.

Trappola 1 — internal_code: leak piantato

Correla col target a +0,92 nel train. Una regola banale internal_code > 50 raggiunge 99,1% di accuracy sul train. Sembra la feature migliore del dataset.

Rilevamento — opinion-probe. analyst_opinion è composta dagli stessi 60 template fissi sia nel train che nel test. Il loro tasso di approvazione per template è un proxy stabile del segnale vero. Una feature genuina deve correlare con quel proxy allo stesso modo in train e in test. internal_code non lo fa:

opmap = train.groupby('analyst_opinion').credit_decision.mean()  # 60 template
tr_op = train.analyst_opinion.map(opmap)
te_op = test.analyst_opinion.map(opmap)

train.internal_code.corr(tr_op)   # +0.46  → segnale reale
test.internal_code.corr(te_op)    # ≈ 0.00 → scrambleato nel test

Distribuzione marginale identica in train e test, ma nel test i valori sono scollegati da ogni altra feature di rischio. I valori sono stati scrambleati.

DROP Senza questa scoperta, il modello avrebbe fatto ~99% in cross-validation e ~52% sul 60% privato.

Trappola 2 — external_pd_score: sparisce nel test

5,2% mancante nel train (utilizzabile). 100% mancante nel test (inutile a inference time).

Beccata con una riga: train.isna().mean() vs test.isna().mean().

5. Diagramma della pipeline

6. Architettura del modello

Tre famiglie di boosting, mediate. La diversità decorrela gli errori.

  • 9 × LightGBM — top-3 configurazioni (random search) × 3 seed, ognuna 5-fold
  • 3 × XGBoost — 3 seed, ognuno 5-fold
  • 4 × CatBoost — 2 configurazioni × 2 seed, 5-fold (encoding categorico nativo per i 60 template di opinion)

Step semi-supervisionato (v8/v10): pseudo-label delle righe test dove l'ensemble base ha confidence ≥ 97%, aggiunte a ogni fold di training con sample_weight = 0,5, e refit.

7. Strategia di validazione

Tre lenti indipendenti, ognuna che cattura un fallimento che le altre mancano.

SchemaCosa cattura
5-fold Stratified K-Fold OOFPerformance media su 25k righe, usata per tunare la soglia
Time split (train ≤ 2024 → validate 2025–26)Drift temporale che un random split nasconderebbe
Rolling next-month harnessSimulazione più fedele del task reale: train finisce 04/2026, test è 05/2026

Per ognuno degli ultimi 6 mesi del train: fit su tutto il precedente, predizione di quel mese → 2.886 predizioni pooled out-of-time. Ogni esperimento è stato giudicato qui, non sul public LB.

Codice: OOF 5-fold + soglia smussata

oof = np.zeros(len(X))

    m = lgb.LGBMClassifier(**params)

# Soglia smussata — evita che l'argmax overfitti il rumore OOF

8. Etica

race e religion sono nel dataset come codici sintetici. Usarle dà +0,7pt di accuracy (misurato).

Abbiamo rifiutato, per quattro motivi:

  • Legale: GDPR (UE), ECOA (USA), Equal Credit Opportunity Act — l'uso di attributi protetti nel credito è illegale.
  • Etico: il target codifica eventuali bias storici degli analisti; riprodurli li amplifica.
  • Pratico: un modello che richiede attributi protetti non può andare in produzione.
  • Metodologico: il brief segnalava esplicitamente queste colonne — usarle significherebbe fallire la domanda etica implicita.
